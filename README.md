# 喵呜机（Meow Machine）

Minecraft **1.20.1 Forge** 模组：内容审核模拟器。玩家用「投稿卷轴」写文本投稿，经过审核
（本地规则 / 人工 / AI 三路）给出结论，结论通过**梗图弹窗**反馈。梗图全部数据包驱动，加表情不用改代码。

- modid：`meow_machine`
- 版本：`0.25.1`（**开发测试阶段**：只走 0.x.y，修 bug 加末位；`1.0.0` 保留给正式发布时再升）
- 状态：可构建、可运行，`gradlew runServer` 冒烟测试通过；纯逻辑自测 92 条
- 网络：18 个包，不用 MenuType（协议号 18）

## 构建与自测

```powershell
$env:JAVA_HOME='C:\Program Files\Java\jdk-17'
$env:GRADLE_USER_HOME='E:\gradle'
cd 'E:\Mod\其它项目\MeowMachine'
.\gradlew.bat build --offline          # 产物 build/libs/meow_machine-<ver>.jar

# 纯逻辑自测（不需要游戏）
& "$env:JAVA_HOME\bin\java.exe" "-Dfile.encoding=UTF-8" `
  -cp "build\classes\java\main" io.github.zgxhzhr.meowmachine.dev.SelfTest
```

> `-Dfile.encoding=UTF-8` **必须整体加引号**，否则 PowerShell 会拆成两个参数（报 `ClassNotFoundException`）。

**装到实例**：把 jar 拷进 `versions/<版本>/mods/`，**先删掉旧版本 jar**——两个同 modid 的 jar 会启动失败。

### 构建踩过的坑

1. `plugins.gradle.org` 会 303 重定向导致 gradle 失败 → 阿里云镜像放最前（`settings.gradle`）
2. Windows javac 默认 GBK → `options.encoding='UTF-8'` + `filteringCharset`
3. `mods.toml` 的 `${...}` 占位符必须在 `processResources` 里 `expand`，否则启动报 `corrupt or misconfigured toml`

### 开发端起服务端的已知坑

`gradlew runServer` 会在启动完成后崩在
`Attempted to load class net/minecraft/client/server/LanServerPinger for invalid dist DEDICATED_SERVER`。
这是 Forge 自己的 `DedicatedServer.initServer` 在 `advertiseDedicatedServerToLan=true` 时去 new 客户端类，
**与本 mod 无关**。把 `run/<世界>/serverconfig/forge-server.toml` 里该项改成 `false` 即可干净启动；
客户端开集成服务器不受影响。

## 审核流程

```
投稿
 ├─ ① 有能终审的人（在线 OP / 名册审核员）且没开「AI 接管」
 │    → 入人工队列，返回 PENDING（等人工，不是「需要协改」）
 │      若 AI 已启用：AI 也先跑一遍，发现存成「AI 意见」随稿进队列（不生效，供人工参考）
 ├─ ② 没人能终审 → 本地规则命中？→ 自动打回（附条号）
 ├─ ③ 本地没命中 → AI 可用？
 │    ├─ 可信结论、无违规 → 通过
 │    ├─ 可信结论、有违规 → 打回（附 AI 发现）
 │    └─ **AI 不可用** → ④ 兜底打回
 └─ ④ 兜底打回（梗图 = fallback「要不直接打回算了」）
```

开「AI 接管」时顺序不同：**AI 先判**，本地规则只当线索交给它（见下文「接管模式」）。

两条硬线：
- **AI 绝不阻塞**：异步 + 超时即放弃，流程必有确定结果。
- **AI 失败 ≠ 通过**：`AiOutcome(available, findings)` 区分「没发现问题」与「没拿到结论」，
  后者走兜底打回，绝不自动过审。

挑梗图优先级：**人工手选** → **规则专属图** → **结论状态图** → **兜底图**。
「说不出依据」打回固定用 `just_return_it`（要不直接打回算了）。

### 投稿端能看到的入口

- 编辑界面底部四颗按钮：新建投稿 / 提交审核 / **我的投稿** / 关闭
- 顶部工具栏：**B 粗体 / I 斜体 / • 无序列表 / 1. 有序列表 / ⊞ 插入表格**
- 「我的投稿」每行：短 id、标题、状态（草稿/待审/已通过/被打回），右侧「查看」「编辑」
  - 查看：只读正文（任何状态都能看）
  - 编辑：草稿/待审/打回可拉回来改；已通过只读
- 「我的投稿」底部还有：**审核后台**（OP，打开完整后台）、待审列表、关闭
- `/meow my` 是同一份信息的聊天栏版本

### 梗图物品（0.18.0）

18 张梗图每张都是一个物品。**收到审核结果时，作者会拿到结果对应的那张**（背包满则掉落）。

- 图标：64px（客户端 blocks 图集 1024×512，塞不进 512px 原图），显示完整原图
- 悬停：名字 + 一篇带剧情的游戏内小故事（中英双语，`item.meow_machine.sticker_<id>.story`）
- 右键：打开放大界面看 512px 原图（气泡文字清晰可读）
- 收集：已收集的种类记在玩家持久数据里（登录时扫背包补记），凑够 8 种发「梗图收藏家」，每拿一张新图都会提示进度

除根节点用 `inventory_changed` 自动触发外，其余都是 `minecraft:impossible` + 业务代码授奖。

## 我的投稿：历史 + 查看 + 编辑

已通过 / 已打回的稿子留在**历史**里（世界存档 `meow_machine_history.dat`），列表能看到状态。

- **查看**：任何状态都能只读正文（含打回/通过的旧稿）
- **编辑**：草稿、待审、被打回的可拉回来改；已通过只读
  - 还在人工队列里的稿子点了编辑会先**撤回**（作者要改，不能让审核员同时审一份要变的稿）
- 底部：**审核后台**（OP）/ 待审列表 / 关闭

## 正文富文本编辑器（0.9.0）

正文按原生 MC百科编辑器的**输入层**实现：编辑者能做出来的只有五种操作，标题靠手打 `[hN=标题]` 文字。

| 工具栏 | 行为 |
|---|---|
| `B` | 粗体：有选区作用于选区；无选区切换「悬挂样式」，之后输入的字带上 |
| `I` | 斜体，同上 |
| `•` | 无序列表：光标段落 ↔ 列表互转，多段选中整段切换，再点一次撤销 |
| `1.` | 有序列表，同上 |
| `⊞` | 插入 2×3 表格（首行表头），插入后光标进第一格 |

键盘：`Enter` 拆段 / 列表内新建项（空项回车退出列表）/ 表格内换行；`Tab`/`Shift+Tab` 表格跳格；`Ctrl+B/I`、`Ctrl+Z` 撤销、`Ctrl+A` 全选、`Ctrl+C` 复制、`Ctrl+V` 粘贴（粘贴会剥掉外部标签）；方向键移动、`Shift+方向键` 扩选、鼠标拖选。

存储：正文以站点同款 HTML 保存（`<p>`、`<strong>`、`<em>`、`<ul>/<ol><li><p>`、`<table><th>/<td valign="top">`），
提交时服务端先 `stripTags` 再交给规则/AI，所以第 26 条的标题结构检查仍然看得到 `[hN=]`。

## 投稿的生命周期 / 多篇投稿

- 草稿是「每个玩家当前那一篇」，存在**世界存档**里（`<世界>/data/meow_machine_drafts.dat`）
- 提交后：本地规则/AI 直接出结论；走人工则入队（队列也落盘，重启不丢）
- 再开卷轴：**默认开一份新稿**；只有「状态仍是草稿、且已经写了内容」的未完成稿才继续打开
  （已提交 / 已打回 / 已通过的内容去「我的投稿」里查看或编辑）
- 想主动换一篇：编辑界面左下角「新建投稿」；旧稿若还在队列里会继续被审（结论按 id 匹配）

## 本地规则（`LocalRules`）

| 条 | 检查项 |
|---|---|
| 3 | emoji / 颜文字（符号类 + `T_T`/`ToT`；不误伤「（Open）」） |
| 10 | 重复内容（整段逐字相同、≥20 字、≥6 汉字） |
| 12 | 句末缺标点 |
| 18 | 正文太短（灌水） |
| 19 | 标点堆叠（`。。。`） |
| 22 | 字符拼的分割线 |
| 22 | Markdown 残留（`##` / `**粗体**` / 手打 `-` 列表 / `\|表格\|` / ``` 围栏） |
| 22 | 粘贴压平（连续 ≥6 条短且无标点的行 / 裸链接行 → 表格列表丢了格式） |
| 23 | 提了版本但没写具体版本号 |
| 24 | `PS.` / `注：` 前缀 |
| 26 | 标题结构：用了 `[hN=]` 就必须从 `[h1=]` 开始、不许跨级；正文 ≥200 字却完全没有标题结构也算 |
| 29 | 冗余句（「欢迎补充」等） |
| 31 | 删除线 |

本地规则只管 **8 条纯格式/可量化**项；其余 **27 条语义类**交给 AI（`AI_ONLY_RULES`），prompt 里始终带全 35 条。
**第 22 条（Markdown 残留 / 粘贴压平）与第 26 条（标题结构）是确定性格式问题**，接管模式下也不让 AI 放行。
编号沿用 MC百科公共编辑规范 1~35，审核意见可直接引条号。

**方括号标记不会被误判**：`[h1=概述]`、`[ban:title_menu]`、`[icon:health=20,点]` 是站点语法，
本地规则不把它们当乱码（第 12 条的句末标点白名单包含 `]`），AI prompt 里也专门写了一段
「百科语法常识」告诉模型不要按第 18/7 条判这些标记。真正会被判的是**结构错**：
标题从 `[h2=]` 开始、`[h1=]` 直接跳到 `[h3=]`，走本地第 26 条。

## 接管模式：AI 优先于本地规则（0.12.0）

开「AI 接管」后，流程变成 **AI 先判、本地规则只当线索**：

- 本地规则命中的条款会作为「疑点」交给 AI，它可以确认、纠正或忽略
- AI 的结论直接生效（通过 / 打回），并可以写一句**附言**（`note`），作者在弹窗里看得到
- AI 返回可选 `sticker` 指定梗图；「通过」只接受 `approved_` 系列，情绪化的打回图不会挂到通过上
- AI 不可用时才退回本地规则（有命中按本地打回，否则兜底打回）
- **确定性格式错误（第 22 条 Markdown 残留、第 26 条标题结构）不让 AI 放行**：
  实测模型会把 `## 核心玩法` / 手打 `- 列表` 判成「格式没有明显问题」，这两条本地必检、
  接管时也会并进结论（AI 仍负责其余条款、附言与选图）

四张原本没有触发条件的图（`helpless`/`kurushi`/`laowu`/`meowmeow`）现在也进了 AI 的目录，
标注「仅 AI 可选」——打回时按情绪挑（无奈 / 难受 / 崩溃求救 / 卖萌敷衍）。

## 梗图：AI 自己选图（0.11.0）

判定交给 AI 时，prompt 里会带上**梗图目录**（每张图一行：id / 触发条件 / `desc` 一句话说明），
模型可以在输出 JSON 里加 `"sticker": "<id>"` 指定用哪张图；服务端校验该 id 存在才采用，
否则退回「按规则号 → 状态图 → 兜底图」的本地顺序。

用途：四张「通过」系列不再随机——有进步用 `approved_progress`、简短合规用 `approved_short`、
有小瑕疵用 `approved_fix`；打回时也能挑更贴切的那张（灌水 / AI 味 / 机翻 / 样式崩）。

## 梗图（数据包驱动，零硬编码）

```
assets/meow_machine/textures/sticker/<id>.png     # 建议 512×512
data/meow_machine/stickers/<id>.json
```

```json
{
  "state": "approved",      // 或
  "rule": 18,               // 或
  "fallback": true,
  "priority": 10,
  "texture": "...",         // 可选；服务端算好路径随结果包下发，客户端据此渲染
  "desc": "又是灌水"         // 可选；给 AI 选图时看的一句话说明
}
```

- 同状态多张时随机取（4 张「通过」不会总出同一张）
- 加载时会对「没有 state/rule/fallback 的图」打 warn（这类图永远不会被选中）
- 加新表情：丢 png + json，**不用改 Java**

## 权限（0.22.1 起角色优先于 OP）

名册是 `Map<UUID, 角色>`，**一个人只有一个身份**；任命另一角色需先撤销。

| 身份 | 终裁 | 看队列 | 写意见 |
|---|---|---|---|
| 审核员 | ✅ | ✅ | ❌（裁决即可） |
| 助理 | ❌ | ✅ | ✅ |
| OP（无角色） | ✅ | ✅ | ❌ |
| **OP 但被任命为助理** | ❌（角色优先） | ✅ | ✅ |

审核终端按角色路由：助理 → 助理面板；审核员 → 裁决面板；无角色 OP → 完整后台；其他人无权限。

名册：`config/meow_machine_reviewers.json`（开局由 `FMLCommonSetupEvent` 加载，重启不丢）
名册条目录的是 **uuid + 玩家名 + 角色**（旧格式只存 uuid→角色的也能读，界面会显示短 uuid）。

### 审核员管理界面

审核终端 → 右键 → 后台 → **「审核员管理」**：

- 上半屏名册（名字 + 角色），每行「撤销」
- 下半屏**在线玩家**，每行直接点「审核员 / 助理」任命（已任命的人只显示「撤销」）
- 还有名字输入框兜底（服务端按名字解析，离线会提示）
- 角色互斥：一个人只有一个身份，换角色要先撤销

### 审核列表看得到正文（0.10.0）

待审列表每行多了「查看」按钮，进入详情页能看到**投稿正文**（服务端剥好标签的纯文本，可滚动），
并可直接在详情页点「通过 / 协改 / 打回」；「返回列表」会重新拉一次列表。
列表本身只显示短 id / 作者 / 标题——以前审核员在列表里根本读不到内容，只能盲判。

### 审核意见界面（0.24.0）

审核详情页只放正文和裁决按钮；意见单独一屏：

- 审核员/OP：`通过 | 协改 | 打回 | 意见 | 返回列表`
- 助理：`写意见 | 意见 | 返回列表`

「意见」界面三栏固定排列，可滚动：**AI 意见**（开 AI 不接管时 AI 的发现）、
**本地规则预检**（对当前稿重跑确定性规则）、**助理意见**（助理留的标注）。

### 通过时选梗图（0.25.0）

审核员点「通过」先打开选图界面：列出 `approved_` 系列（有进步 / 通过 / 简短通过 / 小瑕疵通过），
选一张或交给「默认随机」。服务端校验：通过只能用 approved 图，其它结论不能用 approved 图。

### 插入表格（0.23.0）

工具栏 `⊞` 打开对话框：行/列各 1~8 用 `− / +` 调，**首行表头**可开关；
插入后光标进第一格，`Tab` 跳格。序列化仍按站点格式输出 `th` / `td valign="top"`。

### 裁决原因（0.5.0 起）

审核界面点「打回 / 协改」先进入原因选择，共 15 项：

- 规则号：`1 主观词句 / 3 颜文字emoji / 6 机翻痕迹 / 7 AIGC痕迹 / 10 重复误导 / 12 句末标点 /
  18 灌水无信息 / 19 标点堆叠 / 22 全文样式异常 / 23 版本号不具体 / 24 PS注前缀 / 26 标题结构 /
  29 冗余句 / 31 删除线`
- 「说不出依据」：打回时固定配 `just_return_it`（要不直接打回算了）
- 可补一句话说明（显示给作者）；规则号决定梗图，作者看到「命中：第 N 条」+ 你的说明

## 中文输入（IMBlocker 兼容）

很多中文玩家装了 **IMBlocker**，它只对「白名单屏幕/认识的文本框」打开输入法，
本模组的自定义界面（尤其自绘正文区）它不认识 → 整个界面中文打不进去。

0.5.0 起 `client/ImeCompat` 用反射接入 IMBlocker 的 `FocusContainer.MINECRAFT.setPreferredState(boolean)`：
打开编辑/后台/名册/裁决界面时主动要输入法，关闭时还回去。**没装 IMBlocker 就是空操作**，不影响原版行为。

## AI 配置

默认接 **DeepSeek**（OpenAI 兼容），默认模型 **`deepseek-flash`**（推理型用 `deepseek-reasoner`）。

**配置按存档保存**（0.21.2 起）：`<存档>/data/meow_machine_ai.dat`，字段
`enabled / endpoint / apiKey / model / timeoutSeconds / takeover`。

- 新开存档默认**没有 key**，需要重新填（旧版全局 `config/meow_machine_ai.json` 会在首次进入旧存档时迁移一次，随后把全局 key 清空）
- 填写入口：右键审核终端 → 后台（OP），或 `/meow admin`
- 「AI 接管」开关打开后跳过人工优先，直接走 AI

**密钥在游戏内不泄露**：

- 服务端**从不把 key 下发给客户端**：`AdminStatePacket` 只带「是否已配置」（`hasKey` 布尔）
- 后台输入框永远为空、输入时打码；**留空保存 = 不修改**
- 聊天栏/日志不打印 key（保存日志只写「已设置」/「(空)」）
- 文件层仍是明文 NBT：分享存档/云备份时会带出去，注意别把带 key 的存档发人

**AI 看到的是结构化文本**（0.25.0）：正文按编辑器结构转成 `• 列表项` / `1、有序项` / `| 表格行 |`，
prompt 里说明这些是编辑器生成的真结构，不要当 Markdown 或「压平」；本地规则仍看无结构文本，
所以「粘贴压平」仍然判得出来。

## 已知限制 / 未做

1. **AI 未做真实 endpoint 验证**（代码完整、失败路径已加固；DeepSeek 默认配置已就绪）
2. **名册界面任命的是在线玩家**（离线任命走 `/meow reviewers grant`）；角色互斥，改角色要先撤销
3. 富文本只做了五种（粗/斜/两种列表/表格）；表格可自选行列与表头，但**不支持合并单元格**、字色、上标
4. 网页复制粘贴会丢表格/列表结构（判第 22 条并提示用编辑器重排），不能自动还原
5. `helpless` / `kurushi` / `laowu` / `meowmeow` 四张图没有本地触发条件，只由 AI 选（启动会 warn）
6. 物品图标是 64px 缩放图（客户端 blocks 图集 1024×512，塞不进 512px 原图）；右键可放大看原图
7. 「单人自审」开关已移除（语义有误），目前作者不能终审自己的稿
